## What is TurboUIGen?

TurboUIGen is a three-part AI platform:

| Part | What it does |
|---|---|
| **FigmaMockupGenerator** | Build Figma wireframes from text prompts using an LLM + MCP tools that draw directly in Figma Desktop |
| **WebUIGenerator** | Generate fully interactive web apps (HTML/CSS/JS) from text prompts or existing Figma designs |
| **UIDesignSystem** | A branded React component library (Mobility Global) with Storybook for visual documentation and development |

All three parts share a single React UI served at `http://localhost:3000` and are powered by AWS Bedrock (Claude). The design system establishes consistent branding across everything generated by the platform.

### What it does

Takes a text prompt describing an app and builds a complete, interactive Figma prototype — with screens, navigation, modals, and clickable buttons — entirely through the Figma Plugin API.

### Components

#### 5.1 Figma MCP Server (`figma/mcp/server.py`)

- **What:** An HTTP server implementing the Model Context Protocol (MCP)
- **Port:** 7771
- **Endpoint:** `POST http://localhost:7771/mcp` (JSON-RPC 2.0)
- **Purpose:** Exposes ~19 Figma design tools (create frame, button, text, wire links, etc.) that Claude can call
- **Also exposes:** `ws://localhost:7771/relay` — internal WebSocket for relay.py

#### 5.2 Figma Relay (`figma/mcp/relay.py`)

- **What:** A bridge process that runs on your laptop
- **Purpose:** Connects the MCP server → figma-console-mcp (npm) → Figma Desktop Bridge plugin → Figma Desktop
- **Must run on:** Your laptop (not AWS) because it needs Figma Desktop

#### 5.3 Wireframe Agent (`figma/wireframe/wireframe_agent.py`)

- **What:** An agentic LLM loop that calls Figma tools to build wireframes
- **Model:** AWS Bedrock (Claude)
- **Modes:**

| Mode | What happens |
|---|---|
| `create` (default) | Builds new screens; skips screens that already exist |
| `replace` | Deletes existing screens by name and rebuilds |
| `append` | Adds new screens to the right of existing ones |

### How the Figma Mockup chain works

```
You type a prompt
    ↓
wireframe_agent.py (LLM tool_use loop with Claude)
    ↓  POST http://localhost:7771/mcp
MCP Server (figma/mcp/server.py)
    ↓  WebSocket ws://localhost:7771/relay
relay.py  (your laptop)
    ↓  stdio
figma-console-mcp  (npm package, auto-started by relay)
    ↓  WebSocket port 9223
Figma Desktop Bridge Plugin
    ↓
Figma Desktop  ← wireframe appears here
```

### Starting FigmaMockupGenerator

```
FigmaMockupGenerator\figma\mcp\start.bat
```

This opens two windows:
1. MCP Server on port 7771
2. Relay connecting to Figma Desktop

Then in Figma Desktop: **Plugins → Development → Figma Desktop Bridge → Run** → wait for **"Local Ready"**

### What it does

Generates complete web applications from:
- **Text prompts** → React/TypeScript/Tailwind/Vite app
- **Figma URL** → multi-file HTML/CSS/JS app matching the visual design, with:
  - Separate `data/*.json` files per entity (never a monolithic `data/app.json`)
  - `js/api.js` IIFE module — the only place `fetch()` is called
  - `js/charts.js` — all D3.js v7 charts with hover tooltips
  - `js/router.js` — fires `window._onPageShow(id)` so D3 charts render after sections become visible
  - Desktop vs mobile layout auto-detected from Figma frame dimensions

### Components

#### 6.1 UIGen Agent (`agents/uigen_agent.py`)

- Generates React/Vite projects from Claude
- Manages project lifecycle: create, start, stop, delete
- Tracks projects in `generated/projects-web-apps.json`

#### 6.2 Figma-to-Web Agent — REST API (`agents/figma_to_web_using_api_agent.py`)

- Takes a `design` or `file` Figma URL
- Reads `absoluteBoundingBox` from every frame to detect desktop vs mobile layout
- Calls Figma REST API to export each frame as a PNG
- Extracts prototype wiring (which button → which screen)
- Sends screenshots + wiring + layout hint to Claude → generates HTML/CSS/JS
- `_enforce_rules()` post-processor runs after every generation and refine to enforce data/api/charts/D3 rules regardless of LLM output

#### 6.3 Figma-to-Web Agent — Playwright (`agents/figma_to_web_using_playwright_agent.py`)

- Used for `make` or `proto` Figma URLs (view-only links)
- Launches Edge/Chromium to take browser screenshots
- Falls back to this when REST API gets a 403

#### 6.4 D3.js Chart System

Every generated app includes a shared tooltip system and three base chart types in `js/charts.js`:

| Function | Chart type | Tooltip |
|---|---|---|
| `renderBarChart(id, data, opts)` | Vertical bar chart | Bar label + formatted value on hover |
| `renderLineChart(id, data, opts)` | Line chart with dots | Dot label + value on hover |
| `renderDonutChart(id, data, opts)` | Donut / pie chart | Slice label + value on hover, slice expands |

The shared tooltip uses `position:fixed` + `event.clientX/clientY` so it tracks the cursor correctly across SVG boundaries. Charts render via `window._onPageShow` (not `DOMContentLoaded`) so hidden sections have correct `clientWidth` when drawn.

## UIDesignSystem & Storybook



### Design Tokens (`src/tokens.ts`)

All brand values live in a single file — the single source of truth.

| Token group | What it covers |
|---|---|
| `colors.primary` | Vital Blue `#132445`, Forward Blue `#0064D2`, Morning Mist `#B8EAF5` |
| `colors.neutral` | White → Black scale (6 steps) |
| `colors.accent` | Steady Lilac, Soft Lilac, Vital Spark, Clarity Yellow |
| `colors.semantic` | Success / Warning / Error / Info — colour + background variant each |
| `usage` | Named roles: `pageBackground`, `sidebarBackground`, `primaryButton`, `activeNav`, etc. |
| `spacing` | `xs`(4) → `3xl`(48) — all in px |
| `radius` | `none`(0) → `full`(999) — border radius scale |
| `shadow` | `sm` → `xl` — four elevation levels |
| `components` | Fixed dimensions: `headerHeight`(64), `sidebarWidth`(240), `buttonHeightMd`(40), etc. |
| `typography` | Inter font, sizes from `caption`(11) → `h1`(32) |

Import tokens in any component:
```typescript
import { colors, usage, spacing } from 'mobility-global-design-system'
// or directly:
import { colors } from '../tokens'
```

### 11.2 Figma REST API — Frame export and wiring extraction

**Used by:** `figma_to_web_using_api_agent.py`

**Base URL:** `https://api.figma.com/v1`

**Authentication:** `X-Figma-Token: <FIGMA_ACCESS_TOKEN>` header on every request.

**Endpoints called:**

| Endpoint | What it returns | When used |
|---|---|---|
| `GET /files/{key}?depth=2` | All pages and top-level frames with names, `absoluteBoundingBox` (width/height), IDs | Discovering screens + layout detection |
| `GET /files/{key}?depth=5` | Full node tree including buttons, text, reactions | Extracting prototype wiring |
| `GET /images/{key}?ids=...&scale=1.5&format=png` | Signed S3 URLs to download frame PNGs | Exporting screenshots |
| `GET /files/{key}/nodes?ids={id}` | Single node's full subtree (no depth limit) | Fallback for deep wiring extraction |
| `GET /me` | Authenticated user info | Token validation test |

**URL type routing:**
```
design / file URLs  →  REST API  (structured data + exact wiring + real dimensions)
make / proto URLs   →  Playwright (browser screenshots, wiring inferred)
design URL + 403    →  Playwright fallback (view-only file)
```

**Layout detection from `absoluteBoundingBox`:**
```
frame.width ≥ 1000px  →  DESKTOP — full-width layout, no phone shell
frame.width < 1000px  →  MOBILE  — 390px phone shell centered on dark background
frame.width == 0      →  DESKTOP — unknown dimensions (Playwright path), safe default
```

### 11.3 figma-console-mcp — Figma Desktop Bridge (npm package)

**Used by:** `FigmaMockupGenerator/figma/mcp/relay.py`

**What it is:** A third-party npm package (`figma-console-mcp`) that acts as the bridge between any MCP server and the Figma Desktop plugin. It is **not made by Figma**.

**Protocol:** MCP over stdio (stdin/stdout JSON-RPC). The relay starts it as a subprocess and communicates via pipes.

**Key tool:** `figma_execute` — executes arbitrary JavaScript in Figma's plugin runtime.

**How relay talks to it:**
```python
# relay sends JSON-RPC over stdin
{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "figma_execute", "arguments": {"code": "...js..."}}}

# figma-console-mcp returns execution status over stdout
{"jsonrpc": "2.0", "id": 1, "result": {"success": true}}
```

**Important limitation:** `figma-console-mcp` does **not** return JavaScript return values — only success/failure. All data retrieval uses `figma.notify()` or side effects.

<a name="screenshot-capture"></a>

## Screenshot Capture

Screenshots are taken in two different ways depending on the Figma URL type.

### Path A: Figma REST API (design/file URLs — preferred)

**Agent:** `figma_to_web_using_api_agent.py`

**Step-by-step:**

1. **Discover frames:** `GET /files/{key}?depth=2` → returns all top-level FRAME nodes with names, widths, heights from `absoluteBoundingBox`
2. **Batch export:** `GET /images/{key}?ids=id1,id2,...&scale=1.5&format=png` → Figma renders each frame and returns temporary S3 download URLs
3. **Download PNGs:** Each URL is fetched and saved as `<project>__<nn>__<frame-name>.png`
4. **Naming convention:** `sportshub__01__dashboard.png`, `sportshub__02__players.png`
5. **Save location:** `WebUIGenerator/generated/web-apps/<project>/screenshots/`
6. **Scale factor:** 1.5x by default (configurable) — gives crisp images for Claude's vision model

**Why REST API is better than browser:**
- One clean PNG per frame (no browser chrome, no scrollbars)
- Exact frame dimensions known → correct desktop/mobile layout detection
- High resolution at any scale
- No login required (uses access token)

### Path B: Playwright browser screenshots (make/proto URLs or REST API 403)

**Agent:** `figma_to_web_using_playwright_agent.py`

**Step-by-step:**

1. **Launch browser:** Playwright starts Microsoft Edge using your logged-in profile (so Figma is already authenticated)
2. **Navigate:** Opens the Figma URL in a headless browser
3. **Dismiss overlays:** Clicks away sign-in prompts, "Continue as guest" buttons
4. **Wait for render:** 4 second wait for Figma's canvas to fully load
5. **Full-page screenshot:** `page.screenshot(full_page=True)` — captures everything including content below the fold
6. **Click navigation:** Tries to click nav items to capture different screens (up to 30 unique screenshots)
7. **Deduplication:** MD5 hash comparison — identical screenshots are skipped
8. **Scroll capture:** If only 1 screenshot found, scrolls down in increments to capture long pages

**Screenshot naming:** `<project>__playwright__<nn>__screen-<nn>.png`

**Layout detection:** Playwright screenshots have no frame dimension data — layout defaults to DESKTOP.

**When this path is used:**
- URL contains `/make/` or `/proto/`
- REST API returns HTTP 403 (file is view-only, token lacks editor access)

<a name="figma-wireframe-creation"></a>

## Figma Wireframe Creation

This section explains exactly what happens when you click "Build Wireframe" in the UI.

### The MCP Tool System

The MCP server exposes **19 tools** that Claude can call. Each tool is defined with a JSON Schema (so Claude knows what arguments to pass) and maps to a JavaScript code generator.

**Full tool list:**

| Tool | What it creates in Figma |
|---|---|
| `figma_get_status` | Checks connection, returns page name + frame list |
| `figma_list_frames` | Returns all top-level frames with sizes and positions |
| `figma_create_frame` | Creates a screen/container rectangle |
| `figma_create_rectangle` | Creates a decorative rectangle (cards, dividers) |
| `figma_create_text` | Creates a text node with font, size, color |
| `figma_create_button` | Creates a full-area-clickable auto-layout FRAME (not a rectangle) |
| `figma_create_auto_layout_frame` | Creates a flex container (nav bar, card row) |
| `figma_create_ellipse` | Creates circle/avatar |
| `figma_set_stroke` | Adds border/outline to a node |
| `figma_set_prototype_link` | Wires ON_CLICK → navigate to another screen |
| `figma_add_overlay_link` | Wires ON_CLICK → show overlay/modal on top |
| `figma_set_active_tab_style` | Highlights the active nav tab |
| `figma_set_scrollable` | Makes a frame scrollable in prototype mode |
| `figma_set_prototype_start` | Sets which screen is shown first |
| `figma_wire_all` | Wires ALL interactions in one single JS call (most reliable) |
| `figma_audit_frame` | Inspects frame — reports unwired tabs/buttons |
| `figma_inspect_reactions` | Shows exactly what reactions are set on each node |
| `figma_delete_frame` | Deletes a frame by name (used in `replace` mode) |
| `figma_execute_js` | Runs arbitrary Figma Plugin API JavaScript |

### How the agentic loop works

```
Phase 1 — Setup
  Claude calls figma_get_status to confirm connection
  Claude creates ALL screen frames first
  (destination frames must exist before wiring links)

Phase 2 — Build each screen
  For each screen:
    a. Create sidebar or header (auto-layout frame)
    b. Create content: cards, tables, text, ellipses
    c. Create nav bar with figma_create_button for each screen
       (named: tab-{TargetScreen}-on-{ThisScreen})
    d. Mark active tab with figma_set_active_tab_style

Phase 3 — Build overlays
  For every search bar, filter button, modal trigger:
    Create a smaller overlay frame (300-600px)
    Add content inside it

Phase 4 — Wire everything at once
  Claude calls figma_wire_all with ALL links in one call:
  {
    "links": [
      {"source_frame": "Dashboard", "source_node": "tab-Players-on-Dashboard",
       "target_frame": "Players", "type": "NAVIGATE"},
      {"source_frame": "Players", "source_node": "search-btn-Players",
       "target_frame": "search-results-modal", "type": "OVERLAY"},
      ...
    ],
    "start_frame": "Dashboard"
  }

Phase 5 — QA verification
  Claude calls figma_audit_frame on every screen
  Checks: unwired_tabs, unwired_buttons
  Self-tabs (tab-X-on-X) are intentionally excluded — Figma cannot self-navigate
  Fixes any remaining unwired elements

Phase 6 — Done
  Figma Desktop shows the wireframe
  Click ▶ Play to test prototype interactions
```

### Node naming convention

All node names follow strict conventions so the wiring system can find them:

```
Nav tab buttons:  tab-{TargetScreen}-on-{ParentScreen}
  e.g. tab-Dashboard-on-Players  (on Players screen, links to Dashboard)

Action buttons:   {action}-btn-{Screen}
  e.g. search-btn-Players, filter-btn-Inventory, view-btn-Dashboard

Content nodes:    {role}-{Screen}
  e.g. header-Dashboard, card1-Players, avatar1-MatchDetail

Overlay frames:   {name}-modal or {name}-drawer
  e.g. search-results-modal, filter-modal, confirm-delete-modal
```

### Why buttons must be FRAME nodes (not rectangles)

In Figma's prototype mode:
- A **FRAME** with auto-layout → the entire area responds to clicks
- A **RECTANGLE** → only the exact center pixel responds to clicks

The wireframe agent uses `figma_create_button` (which creates a FRAME) for all interactive elements, never `figma_create_rectangle`.

### Wiring: NAVIGATE vs OVERLAY

```
NAVIGATE  →  Switches to a different screen entirely
             Used for: nav tabs, back buttons, row clicks → detail

OVERLAY   →  Shows a frame on top of the current screen
             Used for: search results, filter panels, modals, drawers
             Centered by calculating: x = (screenWidth - overlayWidth) / 2
```

## Figma to Web App

This section explains the full pipeline when converting a Figma design to a web app.

### Step 1: URL Detection and Routing

```python
url_type = detect("design" | "file" | "make" | "proto")

if url_type in ("design", "file"):
    → REST API path (structured data, exact wiring, real frame dimensions)
else:
    → Playwright path (browser screenshots, wiring inferred)
```

### Step 2A: REST API Path

**a. Parse file key from URL**
```
https://www.figma.com/design/NXsuDdnpf31XBrXubDTm0T/SportsHub?node-id=0-1
                              ^^^^^^^^^^^^^^^^^^^^^^^^
                              This is the file key
```

**b. Fetch frame structure + dimensions**
```
GET https://api.figma.com/v1/files/{key}?depth=2
→ Returns JSON tree: Document → Pages → Frames
→ Extracts: frame.name, frame.id
→ Extracts: frame.absoluteBoundingBox.width, .height  ← layout detection
```

**c. Detect layout type from real frame dimensions**
```
frame.absoluteBoundingBox.width ≥ 1000px  →  DESKTOP layout (full-width, no phone shell)
frame.absoluteBoundingBox.width < 1000px  →  MOBILE layout (390px phone shell centered)
width == 0 (unknown)                      →  DESKTOP (safe default)
```

**d. Batch export all frames as PNGs**
```
GET https://api.figma.com/v1/images/{key}?ids=1:2,1:3,1:4&scale=1.5&format=png
→ Returns: {"images": {"1:2": "https://s3.amazonaws.com/...", ...}}
→ Download each PNG and save locally
```

**e. Extract prototype wiring**
```
GET https://api.figma.com/v1/files/{key}?depth=5
→ Walk full node tree looking for nodes with reactions[]
→ For each reaction: extract trigger type, navigation type, destination frame ID
→ Resolve destination IDs to frame names

If no reactions found (reactions never saved to cloud):
→ Infer wiring from node names:
  "tab-Players-on-Dashboard" → NAVIGATE to "Players"
  "search-btn-Players" → OVERLAY to "search-results-modal"
  "filter-btn-Players" → OVERLAY to "filter-modal"
```

**f. Build wiring prompt for Claude**
```
SCREEN IDs (use in showPage() calls):
  'Dashboard'  →  id='dashboard'  →  showPage('dashboard')
  'Players'    →  id='players'    →  showPage('players')

EXACT PROTOTYPE WIRING:
Screen: Dashboard  (id='dashboard')
  • tab-Players-on-Dashboard (FRAME)  —[On Click]→  showPage('players')
  • view-match-btn-Dashboard (FRAME)  —[On Click]→  showPage('match-detail')
...
```

### Step 2B: Playwright Path (make/proto URLs)

**a. Launch Edge browser with your profile**
```python
# Uses your existing Edge login so Figma is already authenticated
edge_exe = r"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
edge_profile = r"%LOCALAPPDATA%\Microsoft\Edge\User Data"
# Copies profile to temp dir (avoids lock conflicts)
ctx = playwright.chromium.launch_persistent_context(
    user_data_dir=tmp, executable_path=edge_exe, headless=True,
    viewport={"width": 1440, "height": 900}
)
```

**b. Navigate and wait**
```python
page.goto(url, wait_until="networkidle", timeout=45000)
# Dismiss any login/guest prompts
# Wait 4 seconds for Figma canvas to render
```

**c. Full-page screenshot + navigation**
```python
# Screenshot 1: full page (captures below-fold content too)
page.screenshot(full_page=True)

# Try clicking nav items to capture different screens
for item in page.locator("nav a, nav button, ...").all():
    item.click()
    page.wait_for_timeout(2000)
    buf = page.screenshot(full_page=True)
    if not duplicate(buf):  # MD5 dedup
        shots.append(buf)
# Up to 30 unique screenshots
```

### Step 4: `_enforce_rules()` Post-Processor

After every generation and refine, `_enforce_rules()` runs on the full file set to guarantee compliance:

```

  If data/app.json exists: split its keys into separate entity files
  e.g. {"sales": [...], "inventory": [...]} → data/sales.json + data/inventory.json

Rule 2 — js/api.js IIFE module
  If missing or too short: generate a complete IIFE with:
    • _load(file) — fetch + cache per entity
```

### The router.js pattern

Every generated HTML app uses this exact navigation pattern:

```javascript
function showPage(id) {
  document.querySelectorAll('.screen').forEach(function(s){ s.style.display = 'none'; });
  var el = document.getElementById(id);
  if (el) el.style.display = 'flex';
  if (window._onPageShow) window._onPageShow(id);  // fires D3 chart render
}

document.addEventListener('DOMContentLoaded', function() {
  showPage('dashboard');
});
```

### The D3 chart rendering pattern

Charts are rendered inside `window._onPageShow` — never at `DOMContentLoaded` — because hidden `<section class="screen">` elements have `clientWidth === 0`, which causes D3 SVGs to render at zero width and be invisible:

```javascript
window._onPageShow = function(pageId) {
  if (pageId === 'sales-overview') {
    AppAPI.getSales().then(function(data) {
      renderBarChart('sales-chart', data, { xKey: 'month', yKey: 'units' });
    });
  }
  if (pageId === 'forecast') {
    AppAPI.getForecast().then(function(data) {
      renderLineChart('forecast-chart', data, { xKey: 'month', yKey: 'value' });
    });
  }
};
```

## Troubleshooting

### "ModuleNotFoundError: No module named 'agents.uigen_agent'"
Run from the `TurboUIGen/` root directory — `run.py` sets up the Python path. Never run `API/server.py` directly.

### "Relay not connected" in Figma Mockup tab
1. Run `FigmaMockupGenerator\figma\mcp\start.bat`
2. Open Figma Desktop → Desktop Bridge plugin → Run
3. Wait for **"Local Ready"**

### "AWS credentials have expired"
Your AWS session token has expired. Run `aws sso login` (or refresh your credentials), then restart `start.bat`.

### "FIGMA_ACCESS_TOKEN not set"
Add your Figma personal access token to `.env`:
```
FIGMA_ACCESS_TOKEN=figd_...
```
Get it: Figma Desktop → Account menu → Settings → Personal Access Tokens.

### Figma URL gives 403 (view-only)
Use the `design` URL instead of a `make` or `proto` URL:
- Figma Desktop → top-left menu → **Copy link**
- The URL should contain `/design/` not `/make/` or `/proto/`

### Generated app shows as mobile but Figma file is desktop
The frame `absoluteBoundingBox` was not read correctly. Check that:
1. The URL is a `/design/` or `/file/` link (REST API path — reads real dimensions)
2. The Figma frames are genuinely ≥ 1000px wide in the design file
3. If using a `/make/` or `/proto/` URL, the Playwright path has no dimension data and always generates desktop layout by default

### D3 charts appear blank on page load
This is the `clientWidth === 0` issue — charts were rendered while the section was hidden. Ensure `router.js` calls `window._onPageShow(id)` and charts are rendered inside that hook in `app.js`, not inside `DOMContentLoaded`. The `_enforce_rules` post-processor automatically patches this on every build.

### Port 3000 already in use
Change `TURBOUI_PORT=3001` in `.env` and restart.

### UI not showing (blank page or "UI not built")
Build the React app:
```bash
cd TurboUIGen/UI
npm install
npm run build
```
Then restart `start.bat`.

### Storybook won't start
```bash
cd TurboUIGen/UIDesignSystem
npm install   # ensure dependencies are installed
npm run storybook
```
If port 6006 is in use: `npm run storybook -- --port 6007`

### MCP server shows "0 tools"
The MCP server started before the relay connected. Restart `FigmaMockupGenerator\figma\mcp\start.bat`.
