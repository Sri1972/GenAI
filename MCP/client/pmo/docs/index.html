🤖 PMO MCP Client

Unified Multi-Provider LLM Client for PMO Operations

🌟 Overview

What is the PMO MCP Client?

The PMO MCP Client (pmo_mcp_client.py) is an intelligent, production-ready LLM client that provides a unified interface to multiple AI providers while seamlessly integrating with the PMO MCP Server and D3 Chart MCP Server. It enables natural language interactions with your PMO data and automatic visualization generation.

🚀 Key Innovation: One client, four LLM providers (Anthropic Claude, AWS Bedrock, OpenAI GPT, Google Gemini), automatic MCP server orchestration, persistent conversation sessions, and intelligent chart generation!

Key Components

1. Unified LLM Client (UnifiedLLMClient)

Abstract base class with provider-specific implementations:

  • AnthropicClient - Direct Anthropic API integration
  • BedrockClient - AWS Bedrock with SigV4 authentication
  • OpenAIClient - OpenAI/Azure OpenAI integration
  • GeminiClient - Google Gemini integration

2. Session Manager

Handles conversation persistence:

  • load_chat_memory() - Load persisted sessions from JSON
  • save_chat_memory() - Atomic save with fsync
  • set_chat_memory() - Update and persist session
  • 200-message limit with automatic trimming
  • Sessions stored in chat_memory/ directory

3. Chart Integration

Automatic chart generation pipeline:

  • forward_chart_json_to_d3_mcp() - Connect to D3 MCP server
  • create_simple_local_chart() - Fallback Chart.js generation
  • move_and_open_chart() - Save to client directory and auto-open
  • Chart.js data transformation for resource allocation data

✨ Key Features

1. Multi-Step Query Execution

The client supports complex multi-step plans where the LLM can orchestrate multiple MCP tool calls:

# LLM returns a plan JSON: { "plan": [ { "id": "s1", "tool": "get_resource_capacity_allocation", "arguments": {"resource_id": 1, "start_date": "2025-01-01", ...} }, { "id": "s2", "tool": "get_resource_capacity_allocation", "arguments": {"resource_id": 2, "start_date": "2025-01-01", ...} } ] } # Client executes steps sequentially # Appends each result as [TOOL OUTPUT - s1], [TOOL OUTPUT - s2] # LLM receives all outputs and synthesizes final answer

2. Intelligent Data Caching

The client implements smart data reuse to minimize redundant MCP calls:

  • Conversation History Check: Before making tool calls, LLM checks if required data exists in conversation history
  • Deterministic Matching: For resource ID queries, client automatically matches cached tool outputs
  • LLM-Based Matcher: Sends query + cached outputs to LLM to determine if new fetch is needed
  • Large Data Export: Tool outputs >4KB automatically saved to data-exports/ with reference in conversation

3. UTF-8 and Unicode Handling

Robust handling of international characters and emojis:

  • Sets PYTHONIOENCODING=utf-8 on Windows
  • Configures locale for UTF-8 support
  • Replaces problematic emojis with text markers (🔍 → [search])
  • Fallback ASCII encoding for problematic characters

4. Chart Data Transformation

Automatic transformation of PMO data to Chart.js format:

  • Resource Allocation: Converts capacity data to multi-series line charts
  • Time Period Labels: Intelligent date formatting (monthly, quarterly)
  • Project Allocation Details: Grouped bar charts with project-level breakdowns
  • Donut/Pie Charts: Project cost distribution from tabular data

🧠 LLM Providers

Supported Providers

The client supports four major LLM providers with seamless switching:

1. AWS Bedrock (Default)

Default Provider

Configuration:

BEDROCK_MODEL=anthropic.claude-sonnet-4 AWS_REGION=us-east-1 BEDROCK_ANTHROPIC_VERSION=20250514

Features:

  • Uses AWS SDK with SigV4 authentication
  • Supports converse() API for Claude models
  • Fallback to invoke_model() for compatibility
  • HTTP endpoint support with API key or SigV4

2. Anthropic Claude

Direct API

Configuration:

ANTHROPIC_API_KEY=sk-ant-... ANTHROPIC_MODEL=claude-3-sonnet-20240229

Features:

  • Direct Anthropic API integration
  • Full message API support
  • System message support

3. OpenAI GPT

Chat API

Configuration:

OPENAI_API_KEY=sk-... OPENAI_MODEL=gpt-4 OPENAI_BASE_URL=https://api.openai.com/v1 # Optional for Azure

Features:

  • OpenAI Chat Completion API
  • Azure OpenAI support via OPENAI_BASE_URL
  • Streaming disabled for consistency

4. Google Gemini

Generative AI

Configuration:

GEMINI_API_KEY=... GEMINI_MODEL=gemini-pro

Features:

  • Google Generative AI SDK
  • Text generation with generate_content()
  • Message format conversion for Gemini API
💡 Switching Providers: Use the :provider <name> command during runtime to switch between anthropic, bedrock, openai, or gemini without restarting the client!

💾 Session Management

How Sessions Work

The client maintains persistent conversation sessions with automatic memory management:

  • Automatic Session Creation: Each run creates a unique session ID (timestamp + UUID)
  • Named Sessions: Use --session name flag or :use name command
  • Persistent Storage: Sessions saved to chat_memory/ directory as JSON files
  • Memory Limit: Each session stores last 200 messages (configurable via MEMORY_MAX_MESSAGES)
  • Atomic Writes: Uses temp file + fsync + rename for crash-safe persistence
  • Context Preservation: Full conversation history available to LLM across restarts

Session File Structure

Sessions are stored as JSON arrays of message objects:

[ { "role": "user", "content": "List all active projects" }, { "role": "assistant", "content": "{\"tool\":\"get_all_projects\",\"arguments\":{}}" }, { "role": "user", "content": "[TOOL OUTPUT - get_all_projects]\n{...project data...}" }, { "role": "assistant", "content": "I found 45 active projects..." } ]

Session Best Practices

💡 Tips:
  • Use descriptive session names for different analysis tasks (q1_budget, resource_planning)
  • Sessions automatically include tool outputs, so follow-up questions have full context
  • Large tool outputs (>4KB) are automatically exported to data-exports/ and referenced
  • Sessions persist across provider switches - change LLM while maintaining context

📊 Chart Integration

Chart Generation Pipeline

The client automatically generates charts from PMO data using a multi-tier approach:

Tier 1: D3 MCP Server (Preferred)

  • Connects to D3 Chart MCP Server via stdio
  • Calls render_from_dataset tool with Chart.js data
  • Server generates Chart.js HTML with embedded data
  • Returns HTML file path

Tier 2: Local Chart.js Generation (Fallback)

  • create_simple_local_chart() function
  • Generates Chart.js HTML from JSON data
  • Saves to html-charts/ directory
  • Auto-opens in default browser

Chart Types Supported

  • Line Charts: Time-series data (resource capacity over time)
  • Bar Charts: Comparisons (project costs, resource allocation)
  • Grouped Bar Charts: Multi-project allocation by time period
  • Donut/Pie Charts: Distribution (portfolio spend breakdown)
  • Stacked Bar Charts: Cumulative data visualization

Chart Data Transformation

The client automatically transforms PMO data to Chart.js format:

Resource Allocation Example:

# Input: PMO tool output { "resource_details": {"resource_name": "John Doe", ...}, "data": [ {"start_date": "2025-01-01", "end_date": "2025-01-31", "total_capacity": 160, "planned": 120, "actual": 115, ...}, {"start_date": "2025-02-01", "end_date": "2025-02-28", "total_capacity": 160, "planned": 140, "actual": 135, ...} ] } # Output: Chart.js format { "labels": ["Jan 2025", "Feb 2025"], "datasets": [ {"label": "Total Capacity", "data": [160, 160], "borderColor": "..."}, {"label": "Planned Hours", "data": [120, 140], "borderColor": "..."}, {"label": "Available Capacity", "data": [40, 20], "borderColor": "..."} ], "title": "Resource Capacity and Allocation for John Doe" }

Chart File Management

Charts are saved with meaningful filenames:

# Filename format: {chart_type}_{query_hint}_{timestamp}_{hash}.html # Examples: resource_chart_auto_20251028_143052.html donut_portfolio_spend_20251028_144530.html grouped_bar_project_allocation_20251028_150215.html

Location: D:\GenAI\MCP\client\pmo\html-charts\

⚠️ Note: Automatic chart generation is currently disabled by default. Charts are only generated when explicitly requested in queries (e.g., "create a chart showing..."). Use the :chart command for more information.

💿 Data Persistence

Client Data Storage

The client maintains three types of persistent data:

1. Chat Sessions (chat_memory/)

Purpose: Conversation history for context preservation

  • Format: JSON array of message objects
  • Size Limit: 200 messages per session (auto-trimmed)
  • Naming: {session_id}.json
  • Persistence: Atomic writes with fsync
# Session file example D:\GenAI\MCP\client\pmo\chat_memory\session_20251028_143052_a3b4c5.json D:\GenAI\MCP\client\pmo\chat_memory\q1_analysis.json

2. Generated Charts (html-charts/)

Purpose: Visual outputs for PMO data analysis

  • Format: Complete HTML files with embedded Chart.js and data
  • Self-Contained: No external dependencies, works offline
  • Naming: {type}_{query}_{timestamp}_{hash}.html
  • Auto-Open: Charts automatically open in default browser
# Chart file examples D:\GenAI\MCP\client\pmo\html-charts\resource_chart_auto_20251028_143052.html D:\GenAI\MCP\client\pmo\html-charts\donut_portfolio_spend_20251028_144530.html

3. Large Data Exports (data-exports/)

Purpose: Offload large tool outputs to prevent memory bloat

  • Trigger: Automatic when tool output >4KB
  • Format: JSON files with complete tool output
  • Naming: payload_{tool}_{session}_{timestamp}.json
  • Reference: Conversation includes [SAVED_PAYLOAD] {path} marker
# Export file examples D:\GenAI\MCP\client\pmo\data-exports\payload_get_all_projects_session_xxx_20251028_143052.json D:\GenAI\MCP\client\pmo\data-exports\payload_get_resource_capacity_allocation_q1_analysis_20251028_144530.json
💡 Data Management: All three storage locations can be safely cleared if needed. Sessions and exports can be regenerated through new queries, and charts can be recreated from PMO data.

🛠️ Troubleshooting

Common Issues

1. MCP Server Connection Errors

Error: "Connection closed" or "MCP server not found"

Solutions:

  • Verify server path: D:\GenAI\MCP\server\pmo\server.py exists
  • Check Python executable matches virtual environment
  • Ensure PMO MCP server dependencies installed: pip install fastmcp
  • Test server standalone: python server.py

2. LLM Provider Authentication

Error: "API key not configured" or "Authentication failed"

Solutions:

  • Bedrock: Configure AWS credentials (aws configure) and set AWS_REGION
  • Anthropic: Set ANTHROPIC_API_KEY in .env file
  • OpenAI: Set OPENAI_API_KEY in .env file
  • Gemini: Set GEMINI_API_KEY in .env file
  • Reload environment: Restart client after .env changes

3. Unicode/Encoding Errors

Error: "'charmap' codec can't encode character" or Unicode errors

Solutions:

  • Client automatically sets PYTHONIOENCODING=utf-8 on startup
  • If errors persist, clean PMO server data files of problematic emojis
  • The client replaces common emojis with text markers (🔍 → [search])
  • Fallback ASCII encoding applied automatically for problematic characters

4. Chart Generation Issues

Error: "Chart generation disabled" or chart not appearing

Note: Automatic chart generation is currently disabled by default.

Workarounds:

  • Explicitly request charts in queries: "Create a chart showing..."
  • D3 MCP server path: D:\GenAI\MCP\server\charts\mcp-d3-stdio-custom\d3_chart_mcp.py
  • Check html-charts/ directory for generated files
  • Manually open chart HTML files in browser

5. Session Persistence Problems

Error: "Failed to load chat memory" or session not found

Solutions:

  • Check chat_memory/ directory exists and is writable
  • Verify session file exists: ls chat_memory/*.json
  • Session ID sanitization: Only alphanumeric, underscores, dots, and hyphens allowed
  • Start fresh session if corrupted: python pmo_mcp_client.py --session new_session
